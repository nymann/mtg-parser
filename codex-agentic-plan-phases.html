phased parser development

Separate concept grammar, parser binding, unparse, lowering, and card enablement.

This plan defines the long-running phases after the grammar-first shift. Each phase consumes mature artifacts from the previous phase and has its own gates. A concept can be useful before any card passes.

Principle

Do not force one patch to complete every layer. The vertical card pipeline created pressure to hack grammar, AST, parser, unparser, and lowering at the same time. The new model matures concepts horizontally through layers. 

old:
  one card -> grammar + AST + parse + unparse + lowering + corpus pass

new:
  one concept -> grammar maturity
  grammar-mature concept -> AST/parser maturity
  parser-mature concept -> unparse/round-trip maturity
  round-trip mature concept -> semantic lowering maturity
  fully mature concepts -> card enablement

Phases

1. PEST Grammar

Recognize concept syntax with examples and counterexamples. No AST requirement.

2. Parser / AST

Bind matched grammar into structured AST fields. No unparse or semantic requirement yet.

3. Unparse / Round-Trip

Define canonical text and satisfy parse(unparse(ast)) == ast.

4. Semantic Lowering

Map AST into semantic IR and preserve meaning across equivalent surface forms.

5. Card Enablement

Only now run corpus/card fixtures and mark cards passing in batches.

Maturity Model

Layer Input Output Gate Does A Card Need To Pass?
PEST Grammar Rules concepts, corpus examples, grammar neighbours. Grammar rules and concept fixtures. Examples match, counterexamples reject, grammar audit clean. No.
Parser / AST Grammar-mature concept. AST variant or widened fields plus parse branches. Grammar fixture parses into expected AST snapshot. No.
Unparse / Round-Trip Parser-mature concept. Canonical unparse and prop strategy. Round-trip property tests and concept snapshots pass. No.
Semantic Lowering Round-trip mature concept. IR lowering and semantic fixtures. Lowering totality and semantic equivalence tests pass. No.
Card Enablement Concepts mature across all required layers. Generated card tests and corpus status updates. Focused tests and corpus regression pass. Yes.

Concept Registry

The central artifact is a concept registry that records maturity by layer. It replaces the assumption that parser support equals card support. 

concepts/prevention_effect.toml

[concept]
name = "prevention_effect"
rules_terms = ["prevention effect", "damage"]

[maturity]
pest_grammar = "green"
parser_ast = "pending"
unparse_roundtrip = "pending"
semantic_lowering = "pending"
card_enablement = "blocked_on_semantic_lowering"

[artifacts]
grammar_fixtures = "concept_fixtures/prevention_effect.toml"
ast_snapshots = ""
semantic_fixtures = ""
cards_enabled = []

Pipeline Details

Pipeline Reviewer Steps Agent Role Tools Artifacts
Concept-to-PEST Discover concept, collect examples, bound concept, design axes, implement PEST, run grammar fixtures. Boundary design and grammar-only patching. rules_search, corpus_cluster, grammar_query, grammar_fixture_run. Concept file, grammar fixtures, PEST patch report.
PEST-to-AST Choose AST shape, map grammar captures, parse examples, compare AST snapshots. AST design and parser wiring. grammar_slice, ast_surface_map, AST snapshot runner. AST plan, parser patch, AST snapshots.
AST-to-Unparse Choose canonical text, implement unparse, generate strategies, run round-trip. Canonicalization and strategy implementation. Round-trip tests, prop strategy checks. Unparse patch, prop strategy patch, round-trip report.
AST-to-IR Choose semantic model, implement lowering, test equivalence. Semantic design and lowering implementation. Semantic fixtures, lowering totality tests. IR patch, lowering patch, semantic fixture report.
Concepts-to-Cards Find cards whose required concepts are mature, enable card tests, run corpus regression. Usually none; repair agent only if a mature concept fails unexpectedly. Corpus scanner, generated test templates, corpus regression gate. Generated tests, corpus status, card enablement commit.

Commands

# Phase 1: grammar only.
cargo xtask concept-discover --from rules,cards
cargo xtask concept-grammar prevention_effect
cargo xtask concept-grammar-test prevention_effect

# Phase 2: parser and AST.
cargo xtask concept-parse prevention_effect
cargo xtask concept-ast-test prevention_effect

# Phase 3: unparse and round-trip.
cargo xtask concept-unparse prevention_effect
cargo xtask concept-roundtrip prevention_effect

# Phase 4: semantic lowering.
cargo xtask concept-lower prevention_effect
cargo xtask concept-semantic-test prevention_effect

# Phase 5: card enablement.
cargo xtask concept-enable-cards prevention_effect
cargo xtask corpus

The exact command names can change. The important design is that each layer is independently runnable, inspectable, and replayable.

How Cards Become Passing Later

A card should pass only when every concept it uses is mature across all required layers. 

card: example prevention card
required_concepts:
  - activated_ability      mature: all layers green
  - prevention_effect      mature: all layers green
  - target_any_target      mature: all layers green

if all required concepts green:
  generate/enable card tests
  run focused
  run corpus regression
  commit card enablement

Card enablement becomes confirmation that concept layers compose. It is no longer the driver of grammar design.

Acceptance Criteria

  • Each phase can run without pretending later phases are done.
  • Concept maturity is visible in a registry and future UI.
  • Grammar-only concepts do not update corpus status.
  • Parser work consumes grammar-mature concepts instead of raw failing cards.
  • Card enablement is batched from fully mature concepts.
  • Regression gates still protect old cards when card enablement finally runs.
