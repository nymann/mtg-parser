grammar-first pipeline

Concept-to-PEST grammar coverage before card passing.

This plan builds the PEST grammar as a concept inventory using Comprehensive Rules vocabulary and full-corpus Oracle text. It intentionally does not try to make cards pass.

Primary output Grammar concepts with examples, counterexamples, axes, pest rules, and grammar-level fixtures. Parser, unparser, lowering, and card enablement are later phases.

Core Shift

The old unit was one card. That forced every patch to change grammar, AST, parse logic, unparse logic, IR, lowering, tests, and corpus status at once. The new unit is one grammar concept. A concept may be syntactically mature before any card passes.

Rule: this pipeline stops at PEST grammar coverage. It may compile grammar-level tests, but it does not require full AST construction, round-trip, lowering, or card corpus success.

Discovery Sources

Rules-First Discovery

Use qmd over the Comprehensive Rules to identify concept names and boundaries: activated abilities, triggered abilities, replacement effects, prevention effects, costs, targets, zones, counters, damage, durations, and keyword actions.

Corpus-First Discovery

Use all Oracle text to find actual wording shapes, frequency, examples, counterexamples, and variable axes. The rules give meaning; the corpus gives syntax.

rules_search("lex: prevention effect prevent damage")
  -> concept name and CR boundary

corpus_cluster("prevent damage")
  -> "prevent the next N damage"
  -> "prevent all damage that would be dealt by SOURCE"
  -> "prevent all combat damage that would be dealt to RECIPIENT"

Reviewer Flow

1. Discover Concept

Combine qmd rules concepts with corpus phrase clusters.

2. Collect Examples

Gather representative clauses and nearby non-examples from the corpus.

3. Bound Concept

Use rules terminology to decide what belongs in the concept and what does not.

4. Design Grammar Axes

Name variable axes such as amount, source, recipient, target, condition, duration, controller, and zone.

5. Query Existing Grammar

Use grammar_query to find existing rules and safe edit scopes.

6. Implement PEST

Widen or add grammar rules for the concept only.

7. Run Grammar Fixtures

Check examples, counterexamples, ambiguity, and duplicate-shape drift.

8. Mark Maturity

Record grammar maturity and leave parser/unparse/lowering as pending phases.

Tools

Tool Purpose Deterministic Source
rules_search Find rules concepts and terminology. qmd query "lex: ..." -c mtg-rules --no-rerank
corpus_cluster Cluster all Oracle clauses by wording and concept hints. Corpus card JSON and normalized Oracle text.
grammar_query Find existing PEST rules, dependencies, reverse dependencies, and edit scopes. Indexed grammar.pest.
grammar_fixture_run Parse examples and counterexamples at PEST-rule level. A grammar-only test harness over pest rules.
grammar_debt_audit Detect card-shaped rules, duplicate RHS shapes, and excessive rule growth. Existing grammar audit plus concept fixture metadata.

Agent Conversations

BOUNDARY PROMPT
You are defining a PEST grammar concept, not making a card pass.
Given qmd rules hits and corpus examples/counterexamples:
- choose the Comprehensive Rules term
- define what belongs in this concept
- define what is out of scope
- name the grammar axes
Return CONCEPT_BOUNDARY only.

PEST PATCH PROMPT
You are editing only grammar syntax for one approved concept.
You receive grammar_query slices, examples, counterexamples, and axes.
Do not edit AST, parse.rs, unparse.rs, semantic lowering, generated tests,
or corpus status.
Prefer widening existing rules. New rules require a reason tied to the
concept axes, not to one card.
Return PEST_PATCH_REPORT.

Grammar Fixture Tests

Because this pipeline does not make full cards pass, it needs grammar-level tests. 

[[example]]
rule = "prevention_effect"
text = "prevent the next 1 damage that would be dealt to any target this turn"
expect = "match"

[[counterexample]]
rule = "prevention_effect"
text = "destroy target creature"
expect = "reject"

The grammar fixture harness should prove that the rule recognizes the concept family without requiring AST construction or semantic lowering.

Acceptance Criteria

  • The concept has qmd-backed naming or an explicit reason no rules term applies.
  • The concept has at least three corpus examples unless it is intentionally rare.
  • The concept has counterexamples that protect against over-broad grammar.
  • The PEST patch touches only grammar files or grammar fixture metadata.
  • Examples match and counterexamples reject at grammar-rule level.
  • Grammar audit does not flag new card-shaped rule drift.
  • Maturity is recorded as grammar-only; no card is marked passing by this pipeline.
