grammar-first pipeline

Discover grammar concepts before trying to pass cards.

This plan builds PEST coverage from Magic rules vocabulary and full-corpus wording clusters. It stops at grammar maturity: no AST binding, no unparser work, no semantic lowering, and no card pass claims.

In Scope Concept discovery, qmd rules search, corpus clustering, PEST axes, grammar fixtures, grammar maturity records.
Out Of Scope Making a named card pass, generated card tests, parser bindings, round-trip repairs, IR lowering, corpus status changes.

Principle

The old unit was a card. That made one patch responsible for grammar, AST shape, parse logic, unparse logic, semantic lowering, generated tests, and corpus status. The new unit is a grammar concept: a reusable syntax family with rules-grounded meaning, corpus examples, explicit axes, and grammar-only fixtures.

Hard boundary: success in this pipeline means the grammar recognizes a bounded concept. It does not mean any card passes, and it must not update generated card tests or card corpus status.

Operating Flow

1. Map Gaps

Inventory committed concepts against grammar.pest, expand ownership through dependencies, and choose the next unmapped grammar gap.

2. Rules Search

Use qmd to name or check the concept with Comprehensive Rules vocabulary and define the semantic boundary.

3. Boundary Review

Run a read-only agent to decide whether the gap widens an existing concept, starts a new concept, or is blocked.

4. PEST Patch

Run a patch agent to update concept records, grammar fixtures, and PEST syntax for the approved concept boundary.

5. Fixtures

Run grammar-level examples, counterexamples, maturity checks, map updates, and compile/test gates.

6. Maturity

Repair failures, record grammar maturity, and commit the grammar-first iteration without card enablement.

cargo xtask concept-grind --agent codex --max-iterations 1

Discovery Inputs

qmd Rules Evidence

Use local rules search when concept names or boundaries depend on Magic terminology. Prefer Comprehensive Rules terms over invented parser names.

qmd query "lex: prevention effect prevent damage" -c mtg-rules --no-rerank

Corpus Wording Evidence

Cluster Oracle clauses by wording shape, not by card. A cluster should show common stems, optional phrases, replacement axes, and rare variants.

prevent the next N damage
prevent all combat damage
prevent all damage that would be dealt by SOURCE

Grammar Neighbor Evidence

Inspect existing PEST rules before editing. The default move is to widen the closest concept-shaped rule instead of adding a one-card rule.

grammar_query:
  owns: damage_event
  neighbors: prevention_effect, replacement_effect
  reverse_deps: effect_clause

Concept Record

Every grammar concept gets a durable record before a PEST patch is attempted. The record is the handoff between discovery, review, and grammar editing. 

grammar-concepts/prevention_effect.toml

[concept]
name = "prevention_effect"
rules_terms = ["prevention effect", "damage", "event"]
rules_queries = [
  "lex: prevention effect prevent damage",
  "lex: damage would be dealt prevent"
]

[boundary]
includes = [
  "effects that prevent damage events",
  "amount-limited and all-damage prevention",
  "prevention scoped by source, recipient, event, or duration"
]
excludes = [
  "damage replacement that changes recipient without preventing",
  "life gain after damage",
  "destruction or regeneration effects"
]

[[axis]]
name = "amount"
values = ["all", "next_number", "next_variable"]

[[axis]]
name = "event"
values = ["damage", "combat_damage", "damage_from_source", "damage_to_recipient"]

[[example]]
text = "prevent the next 1 damage that would be dealt to any target this turn"
rule = "prevention_effect"

[[counterexample]]
text = "the next time a source of your choice would deal damage to you, prevent that damage"
reason = "same concept candidate, but temporal trigger boundary still unresolved"

[maturity]
pest_grammar = "bounded"

PEST Axis Design

Axis Question Example Values Why It Matters
amount How much of the event is affected? all, next N, X, up to N Prevents separate rules for each quantity shape.
event What event is recognized? damage, combat damage, being dealt damage Keeps syntax aligned with rules concepts instead of card names.
source Who or what creates the event? source, creature, spell, permanent Separates event origin from recipient and target axes.
recipient Who or what receives the event? you, creature, player, any target Prevents recipient wording from becoming duplicated effect rules.
condition When is the concept active? if, as long as, whenever, the next time Forces a boundary decision between effect syntax and trigger syntax.
duration How long does the effect last? this turn, until end of turn, for as long as Keeps temporal phrases reusable across concepts.
polarity Does wording grant, deny, prevent, or replace? can, can't, prevent, instead Highlights cases where similar surface syntax has different rules meaning.

Tool Contract

Tool Role Output Must Not Do
concept-map-existing Inventory grammar.pest against committed concept roots and expanded dependency ownership. Mapped rules, shared grammar primitives, unmapped legacy rules, suggested concept owners. Treat cataloging as maturity progress by itself.
concept-grind Autonomously select the next grammar gap, run boundary and patch agents, gate fixtures, repair failures, update maturity, and commit. Per-iteration prompts, transcripts, fixture results, maturity, grammar debt, and summary. Run add-card, edit generated tests, or claim card pass status.
rules_search Run qmd against local rules to ground concept names and boundaries. Rules excerpts, rule numbers, selected terminology, rejected terminology. Infer card support from rules evidence alone.
corpus_cluster Group Oracle text by clause shape and concept hints. Frequency, examples, counterexamples, skeletons, wording axes. Choose a grammar patch before counterexamples are collected.
grammar_query Inspect existing grammar.pest rules and dependency neighborhoods. Candidate rules to widen, reverse dependencies, duplicate RHS shapes. Suggest a new rule without checking nearby abstractions.
grammar_fixture_run Parse examples and counterexamples at PEST-rule level. Match/reject results, ambiguity report, parse tree snapshots. Require AST, unparse, lowering, or generated card tests.
grammar_maturity Record whether a concept is discovered, bounded, drafted, or green. Machine-readable maturity state and blocking reasons. Mark cards passing or update corpus status.

Grammar Fixtures

Grammar fixtures prove that a rule recognizes a concept family without forcing the rest of the parser stack to exist yet. 

grammar-fixtures/prevention_effect.toml

[fixture]
concept = "prevention_effect"
rule = "prevention_effect"

[[example]]
text = "prevent the next 1 damage that would be dealt to any target this turn"
expect = "match"

[[example]]
text = "prevent all combat damage that would be dealt this turn"
expect = "match"

[[counterexample]]
text = "destroy target creature"
expect = "reject"

[[counterexample]]
text = "target creature gains flying until end of turn"
expect = "reject"

[checks]
ambiguous_parse = "reject"
card_shaped_rule_growth = "reject"
duplicate_rhs_growth = "warn"

Fixtures are scoped to PEST recognition. They may assert match, reject, and ambiguity behavior, but they must not assert AST snapshots or semantic IR.

Maturity States

State Meaning Required Evidence Allowed Next Work
discovered A candidate concept exists. At least one qmd query or corpus cluster with examples. Rules search, corpus expansion, boundary review.
bounded The concept has a reviewed include/exclude boundary. Rules terms, examples, counterexamples, and named axes. Grammar neighbor search and PEST patch planning.
grammar_drafted A PEST patch exists but still needs fixture confidence. Patch report explaining widened rules and any new rules. Fixture repair, ambiguity repair, grammar audit.
grammar_fixture_green The concept is mature for grammar recognition. Examples match, counterexamples reject, ambiguity acceptable, drift audit clean. Later phased work may bind AST/parser support.
blocked The concept cannot mature without a boundary or grammar decision. A concrete blocker, such as overlapping concepts or missing rules terminology. More qmd search, corpus review, or architecture decision.

Agent Prompts

CONCEPT_DISCOVERY
You are discovering a grammar concept, not making a card pass.
Use qmd rules evidence and corpus wording clusters.
Return:
- chosen Comprehensive Rules term, or why none applies
- example clauses
- counterexample clauses
- candidate grammar axes
- unresolved boundary questions

CONCEPT_BOUNDARY_REVIEW
You are approving the scope of one grammar concept.
Decide whether the selected grammar gap widens an existing concept,
starts a new concept, or is blocked as shared/plumbing.
Reject card-shaped boundaries.
Return CONCEPT_BOUNDARY_DECISION only.

PEST_PATCH
You are editing only PEST grammar for one approved concept.
Prefer widening existing concept-shaped rules.
Do not edit AST, parse.rs, unparse.rs, lowering, generated tests, or corpus status.
If you add a new pest rule, explain why no existing rule could be widened.
Return CONCEPT_GRIND_RESULT.

GRAMMAR_FIXTURE_REPAIR
You are repairing grammar-only fixture behavior.
Use examples, counterexamples, ambiguity output, and grammar audit output.
Do not make a named card pass.
Return CONCEPT_REPAIR_RESULT.

Review Gates

  • Concept name is backed by qmd rules terminology, or the record explains why no rules term applies.
  • Corpus clustering has representative examples and nearby counterexamples.
  • Axes are named explicitly and are not encoded as one-off rule names.
  • Existing grammar neighbors were inspected before adding any new PEST rule.
  • PEST changes are limited to grammar syntax and grammar fixture metadata.
  • Grammar fixtures match examples and reject counterexamples at rule level.
  • Ambiguity output and duplicate-shape audit are reviewed.
  • Maturity is recorded as grammar-only.

Explicit Non-Goals

No Generated Card Tests

Do not create, edit, or regenerate files under crates/mtg-grammar/tests/generated/ or generated_patterns/.

No Parser Binding

Do not add AST variants or parse branches while this pipeline is proving grammar coverage.

No Round-Trip Pressure

Do not edit the unparser to compensate for grammar ambiguity. Ambiguity is a grammar maturity blocker.

No Corpus Status Changes

Do not mark cards passing. Card enablement belongs to a later phase after all required concept layers mature.
